Delivery inputs (Store schema)

  • delivery — dataset (default) or webhook. Store schema: start with dataset for reviewable output, then move to webhook after the payload shape is approved.
  • webhookUrl — used when delivery is webhook. Store schema: Slack, Discord, Zapier, or any HTTP endpoint.
  • dryRun — if true, runs without saving results or sending webhooks. Store schema: useful for testing a new watch setup or validating a webhook endpoint before going live.

At least one of searchTerm, chartRequests, or lookupIds is still required. Webhook delivery does not replace those discovery lanes.

Webhook setup after a dataset review

Copied from Store input fields. Fill webhookUrl with your own HTTP endpoint. Review live input schema on the Store page before running.

{
  "lookupIds": [
    "1535144780"
  ],
  "delivery": "webhook",
  "dryRun": true
}

Keep dryRun true until the endpoint is validated. Then set dryRun false and add webhookUrl for a live send.

Pricing and no-change runs
